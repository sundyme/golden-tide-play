# 项目：《金潮号 GOLDEN TIDE》海盗推币休闲游戏 · 专业级垂直切片原型

在 【你的项目文件夹】/ 下开发一个 3D 推币游戏的垂直切片，
桌面和手机浏览器都要能玩。
目标是做成能直接当商业手游宣传 Demo 的品质。美术和手感排第一。内容可以少，
但做出来的每个部分都要达到上线水准。

## 0. 愿景与已定决策
"一台装在海盗船上、会随潮汐呼吸的玩具推币机。"
打开它应该像打开一只精致的微缩八音盒：金光闪闪，手感清脆，
每推下一枚币都让人想再投一枚。

- 名称：《金潮号 GOLDEN TIDE》
- 画幅：竖屏 9:16。推币机"上方投币、下方掉落"的纵深天然适合竖屏；
  桌面端居中显示，两侧延展海景作装饰。
- 工具链：Claude（引擎、玩法、整合、美术总监）+ Codex（2D 生图）
  + AI 3D 生成 + Blender（3D 资产加工中枢）。详见第 7 节。

## 1. 世界观与角色（轻叙事，服务玩法）
- 玩家是海盗船「金潮号」的新船长。船舱里有一台古老的"潮汐宝藏机"，
  传说集齐藏宝图就能驶向金币岛。
- 吉祥物是鹦鹉「铜板」，蹲在机台顶上，负责放大情绪：
  币差一点掉时它紧张地探头，大批掉落时扑翅欢呼，Jackpot 时戴上船长帽跳舞。
  它也负责无文字的新手引导，用动作提示玩家该点哪里。
- 叙事只靠场景、动画和极短的气泡字，不做对话框。

## 2. 玩法设计
### 2.1 机台结构（还原真实推币机）
- 推板就是一个往复移动的上层平台。金币落在推板顶面上，推板回缩时被固定的后挡板刮落到下层台面；
  推板前进时，前脸推动下层币堆，币从前沿掉进收币槽。
- 从前沿掉落算收益；从左右两侧掉落就被大海吞掉（溅起水花，鹦鹉叹气）。
- 加载时先离线跑一段物理沉降，让开局台面呈现"满载、前沿悬着一排将掉未掉的金币"的状态。

### 2.2 玩家的选择（不只是点点点）
- 落点：投币口沿顶部轨道移动，指哪投哪。单击投一枚，长按连投（有限速）。
- 技巧投掷：投币路径上有一个左右摆动的"骷髅门"，金币穿过就触发老虎机。
- 时机：推板所处的位置决定金币落在上层还是下层。
- 道具：老虎机赢来的道具先进道具栏，由玩家决定什么时候用。

### 2.3 特殊物件（4 种，每种都要精致、一眼认得出）
- 💎 宝石：又大又重，很难推落。掉落时慢镜头加特写，奖励高。
- 💣 火药桶：被推落或进入收益区时爆炸，震松周围的币堆。
- 🗺️ 藏宝图碎片：混在币堆里，推落即收集。集齐 5 片触发终局。
- 🪙 巨型金币：老虎机奖品，重量是普通币的 6 倍，能压出一大片。

### 2.4 老虎机（机台顶部中央的实体三轴转轮，不用 UI 弹窗）
- 符号：骷髅（Jackpot）/ 宝石 / 火药桶 / 锚（金币雨）/ 鹦鹉（护栏）
- 护栏：两侧升起挡板，持续 20 秒，期间侧面不丢币
- 概率表写在 config 里，公开可调

### 2.5 招牌机制：潮汐
- 船身一直随海浪轻轻摇晃。投币和老虎机命中会给潮汐计充能。
- 满格触发「大潮」，持续 10 秒：海浪涌起，整台向前倾斜（通过改变重力方向实现），
  推板加速，背景音乐升一档，形成金币雪崩。
- 这是本作和同类游戏拉开差距的记忆点，演出必须到位。

### 2.6 Jackpot 与终局
- Jackpot 演出顺序：0.6 秒慢动作 → 镜头拉远看到整艘船 → 两侧船炮朝台面喷金币
  → 巨型标题字 → 金币瀑布 → 数字滚动结算。
- 藏宝图集齐 5 片后，船驶向金币岛（天色、海色都要转场），一只巨型宝箱翻倒在台面上。
  这是原型的高潮和结局演示。

### 2.7 节奏与数值目标（用自动模拟验证）
- 节奏：每 10–20 秒至少有一次有效掉落；每 60–90 秒一次中型事件；
  每 4–6 分钟一次大事件；8–12 分钟能打到终局。
- 经济：开局 60 枚。币用完时每 4 秒补 1 枚，最多补到 20 枚。
  单靠推落的回报率约 75%，算上各种事件后整体略高于 100%，让玩家感觉"在慢慢变富"。
- 写一个无头模拟机器人连续自动玩 15 分钟，输出数值报告（投入、产出、事件频率、卡死次数），
  按报告调参。
- 公平原则：不暗中操纵物理，节奏只通过事件概率和道具来调。

## 3. 美术方向（最高优先级）
### 3.1 风格定位
风格化 3D 微缩玩具。融合 Supercell《Brawl Stars》的体积感和饱和度、任天堂《动物森友会》
的柔软材质和圆润造型、《Sea of Thieves》的海水和色彩氛围。
整体要像一组摆在阳光下、上了漆的木头和黄铜玩具。

### 3.2 形状语言
- 圆润、粗壮，比例略夸张。所有硬边都倒角，没有锐角，没有细碎噪点。
- 每个玩法物件的剪影都要独特，缩到 64px 也能一眼分清。

### 3.3 色彩与明度
- 时间设定在黄金时刻（傍晚斜阳），金色在暖光下最好看。
- 初始色板（在美术圣经里细化）：深海 #0E3B5C · 潟湖 #2BB3C0 · 奶油沙 #FFE9C2 ·
  金 #FFC83D→#E8961C · 珊瑚红 #FF5A4E · 漆木 #7A3E22 · 黄铜 #C99A4B
- 台面用深色冷调（深青绒面或深色漆木），让金币从背景里跳出来。
- 明度结构：画面里最亮、对比最强、最锐利的位置永远是前沿的"悬崖"区域。

### 3.4 关键资产（逐个打磨）
- 金币是头号资产：要厚实，有边缘齿纹，币面浮雕骷髅和锚。
  材质用 PBR 金属，配环境反射和风格化的高光闪烁。
- 机台：海盗船造型的外壳，配黄铜包边、铆钉、木纹、绳索、小旗、船舵和灯泡跑马灯。
- 其他角色和物件：鹦鹉、宝石（带折射色散）、火药桶、宝箱、藏宝图碎片。
- 环境：风格化的卡通海面着色器（泡沫线、波光），渐变天空，体积云，海鸥，远处的小岛。
- 每个资产怎么做（程序化、AI 生成还是 Blender 建模），按第 7 节的分工决定。
  禁止风格不统一的拼凑素材，禁止默认材质，禁止"程序员美术"。

### 3.5 光照与后期
- 暖色主光，冷色天光，加轮廓光勾边。阴影要柔和，并加接触阴影或 AO。
- 色调映射用 AgX 或 ACES。Bloom 只给金币高光、宝石、灯泡和特效用。
- 用移轴景深（tilt-shift）加强微缩模型感，加轻暗角，开 SMAA 抗锯齿。
- 事件时动态改光：大潮时天色变暗、浪花高光增强；Jackpot 时全场打金色补光。

### 3.6 镜头与构图
- 竖屏 9:16，镜头约 55° 俯视，带轻微透视。
- 前沿放在下三分之一，老虎机放在上三分之一，鹦鹉在右上方，三者构成三角构图。
- 镜头平时有极轻的呼吸漂移；事件时推拉、轻震、慢动作。

### 3.7 VFX（统一卡通风格）
金币闪光、落地火花、水花、卡通烟团爆炸、彩带、金币喷泉、光柱、数字飞入 HUD。

## 4. 手感与音频
### 4.1 手感（Juice）
- 动画遵循预备、挤压拉伸、跟随动作和缓动，禁止线性动画。
- 投币口按下会回弹；金币进槽时有"被吸进去"的效果；数字滚动并弹跳。
- 连续掉落显示连击计数（x2、x3……），音高随之递升。
- 手机端加震动反馈（navigator.vibrate）。

### 4.2 音频（Web Audio 程序合成，要有专业质感）
- 金币声按撞击速度和材质分层，随机调音高和音色，避免机械重复。多枚币同时掉落要合成"哗啦"的瀑布声。
- 配乐用轻快的海盗风（手风琴、拨弦、木琴、手鼓），按潮汐计分 3 层强度递增；Jackpot 时全编制。
- 混音：事件时音乐自动压低（ducking），总线加压缩，防止爆音。
- 音乐和音效可以分别开关。

## 5. UI / UX
- 休闲手游风格：圆角、厚描边、立体按钮，按下有果冻感。中文标题字体要有 Logo 感（用 Google Fonts）。
- UI 尽量做进场景里：潮汐计是机台上的发光仪表，老虎机是实体转轮，金币数写在木牌上。
- HUD 只放必要信息：金币数、潮汐计、道具栏、藏宝图进度。
- 开始界面：标题 Logo 动画，船在海上摇晃，加开始按钮。设置里有音乐、音效、画质三项。
- 用 localStorage 存档（读写包在 try/catch 里）。切到后台时自动暂停。

## 6. 技术规格
- Three.js（ES Module + importmap，从 CDN 加载）+ Rapier3D（WASM）。
  加载 glb 用 GLTFLoader，配合 meshopt 或 Draco 解码。
- 物理：
  - 固定步长模拟，渲染时插值。
  - 金币用扁圆柱碰撞体，调好摩擦、弹性、阻尼和休眠。新投下的币开 CCD（连续碰撞检测）。
  - 推板用运动学刚体（kinematic）。
  - 币堆要稳定：不抖、不穿模。
  - 碰撞体一律用简单几何体，和视觉模型分开。
- 性能：
  - 金币用 InstancedMesh，动态币上限约 250 枚，远处静止的币冻结。
  - 帧率目标：桌面 1080p 60fps，中端手机 60fps。
  - 画质自动分级，配合动态 DPR（像素比）。
- 代码按 scene / physics / gameplay / economy / audio / ui / vfx / config 分模块，所有数值集中在 config.js。
- 调试面板（按 ` 键呼出，用 lil-gui）：可调物理和经济参数，可一键触发各个事件。
- 提供 .claude/launch.json，以及一行启动本地静态服务器的命令。

### 7.3 3D 生成与 Blender 加工
- 通道优先级：
  1. Blender MCP 内置的生成器（Hyper3D Rodin / Hunyuan3D / Tripo，用实际可用的那个）
  2. 我另外提供的 3D 生成 API（Meshy / Tripo / Rodin 等）。key 只从环境变量读取，不写进项目文件。
  3. 回退方案：Blender 脚本建模，或 Three.js 程序化建模。
- 标准流程：
  1. Codex 出参考图。
  2. 图生 3D，每个资产生成 2–3 个候选，挑最好的。
  3. 在 Blender 里加工：
     - 统一比例、朝向和原点。
     - 修破面，减面到预算以内：角色 ≤ 30k 三角面，道具 ≤ 8k，远景 ≤ 15k。
     - **去掉 AI 贴图里烘焙进去的光照**，按 ART_BIBLE 重设风格化材质，必要时重新烘焙 AO。
     - 贴图 ≤ 1024，用 webp 或 KTX2 格式。
     - 可动部件拆开：鹦鹉的头、身体、左右翅膀、尾巴，宝箱盖，船炮炮管。
  4. 导出 glb（meshopt 压缩），放到 public/assets/models/。
- 鹦鹉的动画用拆分部件或简易骨骼，在 Three.js 里程序化驱动（探头、扑翅、跳舞、叹气）。
- 一致性检验：每个模型进游戏后，在统一灯光下截图，和概念图并排对比。风格不统一时重做材质，不能将就。
